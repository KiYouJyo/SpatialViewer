# Spatial Viewer v0.2.2

本版本集中修复真实安装环境中 `SpatialViewer.CadCore` 独立更新可能在发现新版本后下载或暂存失败的问题，不改变已经验收的查看器 UI 布局与交互。

## CadCore 更新器可靠性

- GitHub Release 资产下载增加系统代理路径重试，并在代理链路不可用、返回不完整内容或校验异常时自动尝试直连回退。
- 每一次下载尝试都会同时核对 GitHub 提供的文件大小与 SHA-256；只有完整且摘要一致的内核包才会进入解压和暂存阶段。
- 继续验证 `cadcore-release.json`、x64 架构、来源仓库、SpatialViewer 0.2.x 兼容范围，以及五个核心程序集的版本。
- 更新完成后仍采用安全的“暂存 → 用户手动关闭并重新打开应用 → 启用新内核”流程，不在运行中热替换程序集。

## 可诊断失败状态

- 不再把所有运行时异常压缩成单一的“内核更新失败”。下载超时、网络、SHA-256、存储访问、包校验和版本不一致等阶段会保留独立错误码。
- 详细错误会写入用户内核目录中的 `update.log`；关于页状态保留简洁文本，并通过工具提示提供详细错误信息。
- 如果仍遇到特定机器环境问题，错误阶段可以直接用于后续定位，而不需要再次猜测下载、校验还是本地暂存失败。

## 验收强化

- 签名验收流程现在会真实下载线上 `SpatialViewer.CadCore` Release，按应用更新器的代理重试 / 直连回退策略校验文件大小与 SHA-256。
- 验收随后真实解压内核包、验证 manifest 与五个核心 DLL，并模拟 `versions/<version>` 与 `pending.json` 的完整暂存链路。
- 只有三语资源、Debug/Release、测试、启动 Smoke、在线 Release 契约、运行时下载与暂存、MSIX 构建、签名和离线验收包全部通过后才会输出 v0.2.2 验收产物。

> v0.2.2 仍内置 CadCore v0.2.0 作为回退基线，因此可以继续真实验收发现并下载独立发布的 CadCore v0.2.1。
